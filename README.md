# Playerook KZ — маркетплейс игровых товаров и услуг

Учебный проект по дисциплине «Сетевое программирование» (Go). Playerook KZ — площадка для публикации и поиска игровых аккаунтов, ресурсов и услуг с ценами в казахстанских тенге.

## Анализ продукта

- **Проблема:** жителям Казахстана не хватает простого локального места для поиска игровых товаров с ценами в KZT и удобным общением с продавцом.
- **Целевая аудитория:** игроки-покупатели и продавцы из Казахстана, которым нужны аккаунты, ресурсы или игровые услуги.
- **Аналоги:** FunPay предлагает большой каталог и аудиторию, но ориентирован не только на Казахстан; Playerok обладает узнаваемым интерфейсом, но также не специализируется на локальном рынке. Playerook KZ фокусируется на ценах в тенге и локальной аудитории.
- **Основные возможности:** регистрация/вход, профиль, поиск объявлений, полный CRUD объявлений владельцем, личный WebSocket-чат с историей, лента новостей и распродаж.
- **Интерфейс:** отдельные страницы категорий и объявлений, профиль, кабинет продавца, чат с вкладками личных сообщений и новостного канала; переключатель светлой/тёмной темы.

## Технологии и хранение данных

- Go 1.22, Gin, Gorilla WebSocket.
- PostgreSQL хранит пользователей, bcrypt-хеши паролей и объявления.
- MongoDB хранит историю личных сообщений и новости.
- JWT (HS256, 24 часа) защищает профиль и операции продавца.
- Для демонстрации при запуске автоматически добавляются 30 вымышленных продавцов с объявлениями; повторный запуск не создаёт дубликаты.
- HTML, CSS и JavaScript без стороннего frontend-фреймворка.

Схема PostgreSQL создаётся и дополняется при старте сервера. Индексы MongoDB создаются приложением. Пароли не сохраняются в открытом виде. У профиля есть короткий публичный номер Playerook от 1000, уникальный никнейм и роль; технический UUID не показывается в интерфейсе. В профиле владелец видит, редактирует и удаляет собственные объявления.

## Структура проекта

```text
cmd/server/       точка входа и graceful shutdown
config/           загрузка конфигурации
database/         PostgreSQL, MongoDB и начальные новости
handlers/         обработчики API, CRUD и WebSocket
middleware/       JWT-аутентификация
models/           модели пользователя, объявления и сообщений
routes/           регистрация маршрутов
static/           HTML/CSS/JS интерфейс

```

## Запуск

Требуются Go 1.22+ и Docker с Compose plugin.

```bash
cd go-project-playerook-kz
cp .env.example .env
```

Установи собственный секрет (не менее 32 символов) в `.env` и подними базы:

```bash
openssl rand -hex 32
docker compose up -d
go mod download
go run ./cmd/server
```

Сайт: <http://localhost:8080>. Проверка доступности API: <http://localhost:8080/health>. Для остановки баз: `docker compose down`; данные сохраняются в Docker volumes.

Если базы уже установлены локально, настрой переменные PostgreSQL и `MONGO_URI` в `.env` вместо Docker Compose.

## REST API

Для защищённых запросов передавай заголовок `Authorization: Bearer <JWT>`.

| Метод | Маршрут | Защита | Назначение |
|---|---|---:|---|
| GET | `/health` | Нет | Проверка сервера |
| POST | `/api/auth/register` | Нет | Регистрация |
| POST | `/api/auth/login` | Нет | Вход и получение JWT |
| GET | `/api/profile` | Да | Профиль текущего пользователя |
| GET | `/api/profile/listings` | Да | Объявления текущего пользователя |
| GET | `/api/users/:username` | Нет | Публичная карточка пользователя |
| GET | `/api/listings?q=&game=&category=&limit=&offset=` | Нет | Каталог с поиском и пагинацией |
| GET | `/api/listings/:id` | Нет | Одно объявление |
| POST | `/api/listings` | Да | Создать объявление |
| PUT/PATCH | `/api/listings/:id` | Да, владелец | Полностью обновить объявление |
| DELETE | `/api/listings/:id` | Да, владелец | Удалить объявление |
| GET | `/api/news` | Нет | Новости и распродажи |
| POST | `/api/news` | Да | Опубликовать новость |
| GET | `/ws/chat?with=<username>&token=<JWT>` | Да | WebSocket-чат один-на-один по никнейму |
| GET | `/ws/chat?channel=news&token=<JWT>` | Да | Подписка на новости и акции в реальном времени |

`category`: `account`, `resource` или `service`. Цена передаётся целым положительным числом в тенге. Для ошибки API возвращает JSON вида `{"error":"..."}`; удаление успешно завершается кодом `204`.

### Пример регистрации

```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"name":"Test Gamer","email":"gamer@example.com","password":"test-password-123"}'
```

Импортируй [`postman/Playerook-KZ.postman_collection.json`](postman/Playerook-KZ.postman_collection.json) в Postman. Сначала выполни Register (или Login), после чего коллекция автоматически сохранит токен; затем можно проверить профиль и CRUD объявлений. У 30 демонстрационных продавцов случайные недоступные пароли и адреса `@demo.playerook.invalid`; они предназначены только для просмотра каталога и переписки.

Веб-сайт поддерживает светлую и тёмную темы (выбор запоминается в браузере), показывает отдельную страницу профиля с никнеймом и коротким номером, а каталог и новости доступны гостям. Каталог открывается через выбор категории. В личном кабинете можно посмотреть и изменить свои объявления. Для WebSocket в интерфейсе укажи никнейм продавца (можно нажать кнопку «Написать» в карточке) либо подключись из Postman по адресу `ws://localhost:8080/ws/chat?with=<никнейм>&token=<JWT>`. Сообщение: `{"recipient_username":"<никнейм>","text":"Привет!"}`. Сервер первым отправляет `{"type":"history","items":[...]}`, затем сообщения `{"type":"message","item":{...}}`. Новостной WebSocket подключается по адресу `ws://localhost:8080/ws/chat?channel=news&token=<JWT>`: начальная история и публикации приходят как `{"type":"history","items":[...]}` и `{"type":"news","item":{...}}`.

## Примечание к учебному прототипу

Приложение демонстрирует сетевое программирование и не является платёжной платформой: оно не принимает и не удерживает средства, не обеспечивает escrow и не проверяет передачу игровых аккаунтов. Не размещай в объявлениях пароли или другие секреты.
